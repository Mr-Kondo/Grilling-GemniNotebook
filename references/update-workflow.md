# スキルの更新管理（開発者向け）

この文書はソースリポジトリで更新作業をするときだけ使う。通常のNotebook読解では読み込まない。配布対象にも含めない。

1. 関連Issueと既存ADRを探し、なければ実装前に完了条件付きIssueを作る。
2. 明示的に提供された、匿名化済みの実行結果だけを `feedback/` に保存する。過去セッションやNotebook原文を自動収集しない。
3. 必要なら `knowledge/` の索引から原資料を確認する。索引未収録を「関連知識なし」と解釈しない。対象版・条件・反例・不採用理由を原資料で確認する。
4. 改修仮説と反証可能な成功条件・費用上限・撤退条件を先に決める。知識の追加だけで実行ルールを変えない。
5. 改善用と最終評価用の入力を分け、同条件で変更前後を比較する。意味の品質、引用、時間、費用、知識維持の手間を区別する。未測定値を推計で埋めない。
6. 別エージェントのレビューを受け、妥当な指摘を反映し再検証する。変更の採否と理由をIssue・ADRに残す。不採用の変更は戻し、不採用理由は消さない。
7. 採用変更をマージ・リリースし、インストーラーでMacの既存配置を更新・ハッシュ照合する。確認できない環境は未確認として残す。
8. マージ済みブランチと今回の一時物を片付ける。置換前バックアップは検証後に削除するが、独自変更や復旧に必要なものは理由付きで保持する。

`knowledge/`・`adr/`・`tests/`・`feedback/` は実行用インストールにコピーしない。公開リポジトリには匿名化した判断と再現手順だけを置き、実行ログは公開しない。
